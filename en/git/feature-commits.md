## Commit Convention: Feature-Centric Commits

Commits should be feature-centric, where each commit represents a complete feature rather than individual file changes.

* Most commits should be `feat`
* A `feat` commit includes all changes required for the feature to work, including code, tests, and supporting documentation when needed
* Do not split commits by file type (e.g., separate commits for code, docs, etc.)
* Commit features as single, self-contained units of work

This keeps history clear, reviewable, and aligned with feature delivery.
